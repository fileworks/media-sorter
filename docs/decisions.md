# Maintained decisions

Current choices, not a session log. The linked contract owns implementation detail.
When a lasting choice changes, update its row and the affected instructions in the
same change; record the new date/reason. Release observations belong in release
evidence rather than this table. Personal/security setup never belongs in a public
decision record. Missing private notes do not block ordinary work.

| 2026-10-18 | The org-owned `fileworks-release` GitHub App pushes release commits and tags | The previous fine-grained PAT belonged to a retired personal account and expired on a calendar. A one-hour App installation token, minted from an organization variable and secret, triggers `release.yml`, bypasses the `main` ruleset as an explicit actor and depends on no person. It is minted after the candidate passes, so no push credential exists during installs or builds. | [releasing](development.md#releasing) |
| 2026-10-18 | One Version Release dispatch previews, verifies and ships; versioning and building stay separate workflows | Releasing needed two dispatches and gave no view of what would ship. Version Release now writes the next version, changelog and commits to its summary (`dry_run` stops there), reuses or starts the Release candidate for the exact SHA, retries its failed jobs once, and only then tags. It stays separate from Release so the token that may push to `main` never reaches the long third-party builds and a tag can be rebuilt without a new version. Pushes with the `fileworks-release` App token (no `GITHUB_TOKEN` fallback), installs tooling with `--ignore-scripts`, and tag builds are never cancelled mid-publish; package uploads retry once after runner network failures. | [releasing](development.md#releasing) |
| 2026-10-17 | Wait for WebView2 to exit before removing its isolated smoke profile | Release candidates kept failing on new lock types (`.pma`, Code Cache `.tmp`, then "directory not empty") because cleanup raced a browser that outlived the app, and each fix allowed only the latest file. Cleanup now waits up to 60 s for processes using that profile, then retries access-denied, sharing and directory-not-empty errors anywhere inside the profile for 30 s. A lingering browser, errors outside the profile and persistent locks still fail. | [release checks](development.md#releasing) |
| 2026-10-17 | macOS packages build on macOS 26 from GitHub-hosted ffmpeg and verify each distinct Mach-O once | Release candidates failed three ways. `codesign` rejected PyInstaller's `Python.framework` symlink and, because Tauri dereferences symlinks into the app, its real copies too ("ambiguous bundle", "invalid Info.plist"); signing now skips symlinks, the seal check verifies each distinct Mach-O at its deepest path and accepts only byte-identical copies elsewhere, and CI's macOS packaging job runs that check on every PR. evermeet.cx kept answering HTTP 429 to release runners, so Intel now uses the same pinned descriptinc 7.1 assets as Apple Silicon (static, macOS 11+), with `Retry-After` backoff and a SHA-256-verified Actions cache. Release runners match CI's macOS 26 image. | [development](development.md#quality-gates) |
| 2026-10-12 | The desktop window keeps at least 640 × 480 | Every stage was checked to fit 640 × 480 in English and German without sideways scrolling (below 768 px the stepper shows only the current stage); the shell now refuses to shrink below the size anything was verified at. | [UI conventions](frontend-conventions.md) |
| 2026-10-12 | Platform-labelled screenshots skip the model | File names platforms give screenshots and the iOS/macOS "Screenshot" user comment are precise, free and explainable; such files go to the screenshots category and get the screenshot tag, and Review names the signal. Burst sharpness ranking already covers OPT-07; OCR was not added (new runtime and model pack for detection SigLIP already handles). | [evaluation](local-ai-evaluation.md#screenshots-from-platform-metadata) |
| 2026-10-12 | Setup offers category names drawn from the user's photos | The tested suggestion API had no user interface. Setup now samples up to 150 input photos, clusters them locally and offers names in the interface language that the categories do not already contain; each is a one-click, reviewable addition and nothing changes automatically. | [settings reference](settings-reference.md) |
| 2026-10-12 | Local AI ships the full-precision SigLIP vision tower (pack v2) and converts colour profiles to sRGB | On the held-out fixtures fp32 vision raised tag F1 from 0.865/0.886 to 0.921/0.923 (English/German; 0.920/0.921 after the de-duplicated re-run) and categorization accuracy to 97.1 % (97.0 % re-run) for 13 ms and 257 MB more; fp16 was slower and needs reduced graph optimization. v1 keeps working until v2 is installed, and the upgrade reuses its verified identical files (372 MB download). Display P3/Adobe RGB/CMYK pixels read as sRGB lost accuracy; converting restored it. | [model distribution](model-distribution.md) |
| 2026-10-12 | Local AI scoring is calibrated on public held-out fixtures | The categorizer covered 5 % (English) and 0 % (German) of reviewed images and German tags were a third wrong. On 227 pinned Commons fixtures with a frozen calibration/held-out split, categories now use the best prompt, the model's own logit scale and an absolute floor (all fixtures: 61.7 % of the 162 with an expected category assigned, 95.4 % accuracy when assigned), bundled categories score with English prompts, and tags need a per-language margin over the background (German F1 0.783 → 0.888). Templates stayed; the native tag sigmoid scored lower. | [evaluation](local-ai-evaluation.md#held-out-evaluation--2026-10-12) |
| 2026-10-12 | One in-memory image embedding per file, shared by categorization and tagging | Preview decoded and embedded each image twice, and runs re-embedded it again. A byte-bounded (64 MB) LRU keyed by file identity, modification evidence, model and preprocessing version now serves both consumers; it stays in memory because embeddings are derived personal data, and reviewed runs embed nothing at all. | [evaluation](local-ai-evaluation.md#image-embeddings) |
| 2026-10-12 | Review shows, freezes and edits the AI tags a run writes | Tags were first computed during execution and written before anyone saw them. Preview now proposes them, the plan freezes them, Review can remove or add tags per file, and a run writes exactly the reviewed tags without running the model again; edits persist with the plan's Review state. | [API contract](kb-api-contract.md#reviewed-content-tags) |
| 2026-10-12 | Video frames for local AI keep their failure reason and stop on cancellation | Missing ffmpeg, timeouts and undecodable frames looked exactly like "nothing matched", and a cancelled file could wait through a 30 s probe and five 15 s frame decodes. One sampler now records the first failure and decoded count, logs a video that yielded nothing, normalises frames before averaging, and stops between steps; a cancelled file is left out of the preview plan and recorded as cancelled, never as corrupt. | [evaluation](local-ai-evaluation.md#video-frames) |
| 2026-10-12 | Execution reuses the reviewed category and records why one was rejected | Re-classifying during the run cost a decode and inference per file and could contradict the reviewed placement; the run now takes category, confidence and margin from the frozen plan and classifies only without one. Provenance records the margin and the first failed gate (background, confidence or margin), so Review no longer blames confidence for every rejection. | [evaluation](local-ai-evaluation.md) |
| 2026-10-12 | Location tags are a separate opt-in | Place and country names are personal and travel with shared tags, so enabling content tagging no longer adds them. `ai_location_tags_enabled` is off for new users; configurations saved before it keep location tags when tagging was on. | [settings reference](settings-reference.md) |
| 2026-10-12 | Local AI encodes each text alone and releases the idle text tower | The int8 text tower quantizes per batch, so a label's vector depended on its neighbours; single-text encoding is deterministic, equally fast and cut memory after the first tag from 2.54 GB to 548 MB. Text vectors live in a bounded read-only LRU, the text tower is released after 30 s idle, and loading is locked so concurrent first use builds one encoder. | [evaluation](local-ai-evaluation.md#text-encoding-since-2026-10-12) |
| 2026-10-12 | Location tags come from a bundled GeoNames extract | `reverse_geocoder` was never collected into the frozen backend, failed silently, was LGPL and pulled in SciPy. The checksum-pinned `cities1000` extract (city sections and historical places removed) answers within 25 km, validates coordinates, treats `(0, 0)` as a real position, reads video ISO 6709 locations, names countries in the interface language and ships CC BY 4.0 and CLDR attribution; packaged smoke checks require the data. | [evaluation](local-ai-evaluation.md#location-tags) |

Windows runs local AI on the CPU and says so. | [settings](settings-reference.md), [model distribution](model-distribution.md) |
